# Android 2.23.2.54 知识内容保存前历史校验索引优化

## 真机日志与问题

2026-10-24 用户提供 vivo V2352A（Android 16）十倍率 2.23.2.53 的诊断日志。知识内容保存多次出现 `snapshot_preflight` 分钟级等待，其中有 1268524 毫秒、1254212 毫秒、497192 毫秒、458848 毫秒、250370 毫秒等记录；同期 `draft_write_lock` 也长时间等待。已有 SQLite 提交与恢复镜像时间显著短于这些异常预检。但是阶段计时为墙钟时间，可能包含 Android 后台冻结与任务调度等待，不能推断所有时间均为 CPU 执行历史校验。

源码生成审查发现：`android_startup_stream.rs` 的中间模板原先含有 `NOT INDEXED` 全表扫描，但随后 `android_local_read_efficiency.rs` 已在最终生成阶段将其改写成工作区过滤的索引友好查询。因此不能断言旧版 APK 实际仍执行跨账户全表扫描。新版本改为在上游明确使用 `INDEXED BY snapshot_history_workspace_time` 强制历史索引，并协调下游源码生成规则，避免互相覆盖。**真实的大耗时仍是每次写入前的完整历史认证及其伴随的墙钟等待，单纯强制索引并不能保证根治。**

## 修改

1. Android 35+ 历史快照读取显式强制使用 `snapshot_history_workspace_time` 索引，按索引中同样的时间与主键顺序遍历当前账户全部历史行。当前快照使用其原有主键索引。不引入临时排序。
2. 完整保留每行 SHA256、封装验证、版本验证、当前快照校验、预期总行数断言、事务绑定、并发验证缓冲上限、异常回退、隔离记录以及 JSON 主备恢复文件检查。此改动不绕过已有历史完整性保护。
3. 在保存预检里记录 `phase=preflight_native_verification` 的墙钟耗时和已验证行数，沿用应用的脱敏诊断通道。不记录页面内容、工作区标识、账户或密钥，可与现有 `snapshot_preflight`、`draft_write_lock` 分段日志对照。
4. Android 候选版本为 2.23.2.54 / versionCode 22323。Windows 版本、数据库模式、同步格式与原签名身份均不变。

## 测试与验收

Rust 源码生成器增加最终 Kotlin 查询结构检查与真实 SQLite 回归测试：构造 1500 行跨账户、时间戳重复的历史记录，确认原扫描和索引扫描包含完全相同的目标行，检查 `EXPLAIN QUERY PLAN` 使用账户历史索引且没有全表扫描或临时排序。原 JVM 预检测试仍检查无法校验、快照变化、未来版本与隔离记录必须回退或阻止保存，生成器测试检查新日志不包含内容或账户标识。

构建需依次通过 Rust 源码生成器、Android JVM 单元测试、lint、原正式证书签名 Release APK 与 SHA256。真机应保留原有账户及完整历史数据，测试前台编辑、退回、后台恢复、图片导入、跨账户切换及异常恢复，采集新旧阶段耗时。尤其要检查大量属于同一账户的历史行，因为即使索引有效，全部目标历史快照仍须逐行验证，本 PR 主要提升生成链一致性及诊断可观测性，不承诺解决已经按工作区索引查询时的全部分钟级等待。

本 PR 独立评审，不合并、不上传用户原始诊断日志。实际构建与性能结果以 CI 和设备验收为准。
