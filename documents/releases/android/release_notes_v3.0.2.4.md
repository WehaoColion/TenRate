# Android 3.0.2.4 知识模块保存性能修订

## 故障证据

Android 3.0.2.2 的真实设备诊断显示，知识页面创建的 snapshot_preflight 分别耗时 501941 毫秒和 261262 毫秒，操作总耗时分别为 503498 毫秒与 262859 毫秒。历史快照校验涉及约 7198 行，而 SQLite 提交通常约 1 至 3 秒。保存期间伴随密集的大对象垃圾回收。现有轻量模拟器创建保存测试约 4745 毫秒通过，却未覆盖真实历史规模。

## 修订

在 Rust 源码生成链路中，知识保存的 preflight 首先使用同一 SQLite 写事务读取历史 schema/digest 元数据，并要求当前快照通过原生有效载荷摘要、完整性封套、列版本和 JSON 内版本双重验证。满足条件后，仅对已验证的当前快照发放**本事务内**的 current-only 收据，跳过几千条历史大 JSON 的重复读取、解码和分配。旧版未封套的历史仍原样保留，在恢复环节继续做历史完整性认证。

遇到历史声明未来 schema、缺失必要摘要、缺失或损坏当前快照、原生验证失败或数据库版本标记变化时继续走原有完整历史检查与恢复保护；任何收据不可跨工作区、事务或错误复用。隔离区数据及主备 JSON 恢复镜像继续在提交前检查未来版本，不因为 current-only 而跳过。

增加 preflight 事务等待时长诊断，不收集知识文本、账户或工作区名称。保留 SQLite 的同步事务提交、恢复镜像与退出时的可靠写入。Windows 和服务器格式不变。

## 验收

GitHub Actions 在 Android API 35 模拟器安装正式签名的 3.0.2.4 APK。Rust 验收驱动先创建基准页面，停进程并在实际 SQLite 数据库注入 7200 条有效旧式历史快照，再启动应用新建知识页面。检查保存状态清除、日志确认为 current-only、本地页面在强制停止及重启后仍存在，同时保存界面截图、UI 树、历史数量与日志证据。

版本名 3.0.2.4，versionCode 30006。本候选须以 GitHub Actions 实际运行结果为准，不能因构建成功而宣称性能验收通过。
