# Android 2.23.2.48 大规模历史读取性能改进

候选 APK 版本为 2.23.2.48，versionCode 22317。该改动基于 PR #42，PR #42 又基于 #41，必须依次合并才构成完整优化。当前仅变更 Android 启动历史验证调度、缓冲回收、测试、版本和候选发布工作流。Windows 客户端、同步协议、账号及历史快照格式不变。

## 代码确认的瓶颈

在完全读取历史快照的原生验证流水线里，最多允许每个工作线程同时拥有两条待验证任务；但原实现以提交顺序调用 Future.get()，若头一条记录很大，即使后续多条记录已验证完毕，读取线程仍要等待最先提交的结果，不能把后续任务持续交给空闲工作线程。这是队首阻塞，存在大小悬殊的快照时会放大首屏等待时间。

另一个内存压力来自按 workers * 2 + 1 分配可复用缓冲名额，且最大历史记录的字节数组会一直留在缓冲池，导致加载期间大数组长时间存活。

## 修复

改为 ExecutorCompletionService 根据实际完成顺序领取结果，待处理任务依旧不得超过 workers * 2。完整计数、单条失败即拒绝、等待所有线程退出、事务身份验证、未来版本拦截与回退恢复路径不变。不管任务完成先后，全部 expectedRows 才算验证完成，绝不减少校验行数。

缓冲池降为 workers + 1 个可复用数组，使一条记录正在读取时，其他线程仍能认证；超过 4 MiB 的数组在验证结束后不保留到池内，以降低历史含异常大文档时的内存保留。每次读取和原生验证仍传入完整实际长度，绝不截断。

新增 JVM 测试：制造一条被阻塞的大快照，验证后续小快照完成即可继续喂给工作线程；拒绝行、缺行不得产生成功回执；超过复用上限的快照仍收到完整头尾和长度。源码生成 Rust 测试约束完成顺序、边界和容量。

## 构建、发布及真机边界

工作流只在原版本检查、完整 release JVM 测试、lint、原证书签名核验和产物 SHA256 均通过后，才将 2.23.2.48 APK 发布为 GitHub Releases 预发布，存在同名文件只允许完全一致的字节，禁止覆盖不同 APK。若云端失败，不得把 PR 或 APK 称为通过。

本优化主要改善历史快照尺寸不均、内存受限设备。每次冷启动仍然完成当前账号历史验证；没有获得用户手机上的 StartupLatency 数据，不能承诺已实现秒开，也不把主机领域测试与手机真实耗时混淆。合并、签名候选是否发布、实际真机安装和端到端同步应分别核对。
