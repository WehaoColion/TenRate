# Android 3.0.2.5 知识保存性能修订

本版本针对 3.0.2.4 仍然存在的数分钟保存等待开展第二轮修订。所有业务实现变更仍由 Rust 源码生成链路产生；Android 构建配置只同步版本信息。

## 核心变更

将 snapshot_history 的安全元数据检查拆分成工作区与 schema_version 的覆盖索引查找、以及仅为摘要/封套缺失记录建立的局部索引查找。避免健康历史记录逐条访问包含大型 JSON 快照的主表页。数据库架构版本从 5 安全迁移至 6；保留全部历史快照、摘要、隔离和恢复逻辑。

保留原有 AppStateDatabase 监视器锁语义，外层开启事务前单独计时监视器排队和 SQLite BEGIN/数据库打开等待。超过一秒的真实等待写入 notes.local_save.latency 的结构化诊断，并保留 Logcat 标签。已有 snapshot_preflight 阶段继续记录整体耗时，不再把它误认为完全由 Rust 校验引起。

启动仍检查缺失封套的旧式历史并按原逻辑认证；保存只在当前快照经过认证、历史版本和摘要元数据安全时走快速路径，不因为旧历史缺失封套而每次全量解码。未封装或缺失摘要的历史记录在清理时予以保留，直至明确验证与迁移。

## 验收边界

Rust 测试验证含数千行历史的 SQL 查询计划、不同工作区隔离、未来版本与缺失封套触发安全回退。GitHub Actions Android 35 模拟器安装正式签名 APK，完成知识页面新建、SQLite 权威数据检查及进程重启恢复。模拟器注入的是轻量旧式历史，不能据此声称真实大工作区性能已通过。

本版本优先消除可证明的历史元数据查询成本和锁等待盲区。独立知识页面的增量持久化架构仍需单独迁移与恢复协议评审，不能在此轮中冒险替换。
