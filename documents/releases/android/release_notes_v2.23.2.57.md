# Android 2.23.2.57 启动工作台优先显示

## 用户体验与根因

在已有启动优化后，Android 仍先运行本机快照验证、账号恢复、便签草稿与媒体修复。虽然这些步骤已移至后台协程，`GridTimerScreen` 依然通过 `isInitialized` 返回全屏加载指示器，导致用户在数据库恢复期间完全看不到工作台。旧的 `ReportDrawnWhen { initialized }` 也把“页面绘制完成”与“数据恢复完成”混为一谈。

## 变更

本版保持 `TimerRepository` 原有 `CoroutineScope(SupervisorJob() + Dispatchers.IO)` 恢复任务与 `initializationJob` 生命周期不变。未初始化时，立即显示和正式应用一致的 Compose 工作台外框，包括品牌标题、计时／便签／知识／记账栏目和当前栏目占位卡。栏目在等待期间可选择，但由于数据尚未认证，暂时显示占位内容；恢复后自动切换到已认证的完整工作台。首次可见帧的绘制报告不再等待磁盘恢复结束。

原有 `isInitialized` 门槛继续保护 `appData` 的读取、计时通知、写入和依赖账户身份的操作。未认证的 `AppData.default()` 不会作为真实用户数据渲染，首次数据写入也不会在初始化前进行。快照校验、历史扫描回退、损坏隔离、未来格式保护、恢复日志与媒体修复没有删减，后台任务不会因工作台绘制而取消。

## 限制和验收

这项改动主要解决“先看到应用再等内容”的**可感知启动时间**，不是承诺数据库恢复本身更快。等待期间切换的栏目只用于显示对应占位卡，完整数据就绪后仍进入正式工作台默认导航，不能误认为已经打开了数据页。真正的便签编辑、计时和数据操作需要等待权威工作区初始化完成。首次打开仍可能受系统进程创建、设备 IO、Compose 初始化影响。

Android 候选版本 `2.23.2.57`、versionCode `22326`。仅修改 Android 界面源码生成器及构建发布配置，不变更 Windows、存储格式、账户身份、签名证书或同步协议。

回归检查应覆盖：从强制停止开始的第一次界面绘制与 `StartupLatency ready` 分离，恢复中栏目占位交互，恢复完成后真实数据正确替换，正在运行的计时器/通知不被空状态覆盖，未认证期间不落盘，以及旧/损坏/未来格式快照的保守恢复。Rust sourcegen 检查与 Android JVM 测试、lint、正式签名 APK 构建均以 GitHub Actions 的实际状态为准；真机性能仍待验证。本 PR 不自动合并。
