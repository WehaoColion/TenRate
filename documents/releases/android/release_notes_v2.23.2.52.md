# Android 2.23.2.52 图片导入候选版

## 反馈与问题

2026-10-23 用户反馈：知识目录的文档编辑器导入多张图片时，“正在导入图片…”占位块持续十几分钟，顶部显示保存中。截图没有阶段日志，不能断定是哪一环节造成全部等待。

源码显示，每张图片会被单独进行文件写盘及完整 SHA-256 验证，然后针对整个工作区执行 JSON/JNI 转换和完整快照持久化。在批量导入中，每张图片都等待写锁内的全量工作区保存完成才更新占位符。

## 本次修改

1. 在图片文件流复制过程中增量计算 SHA-256，减少一次额外的整文件哈希读取。保留 fsync、持久导入日志、原子文件发布、发布后哈希核验，以及文件大小和分辨率限制。
2. 使用现有的 Kotlin 单便签附件转换逻辑，省去每张图片把整个工作区往返 JSON/JNI 的开销。
3. 图片已经写盘并留下持久恢复日志，且仍属于原工作区、原便签时，更新内存状态并解除导入占位。使用现有 1000ms 防抖写入合并整份工作区快照，避免六张图引起六次全量快照写入。图片显示并不代表全量快照已经提交，保存成功应以真实持久化回执为准。
4. 成功提交匹配工作区的完整快照后，后台清理已成功导入的恢复日志。若持久化失败、任务被更新取代、账号切换或后台进程结束，保留日志供已有恢复与重试逻辑使用。
5. 不再将“正在导入图片…”重复写入图片说明文本，图片占位块仍显示原有状态。

## 验证条件与限制

- Rust sourcegen 回归测试：唯一改写锚点、流式摘要、完整文件同步、原子发布、发布后完整校验、工作区隔离、成功提交后才清理日志、图片状态文本。
- GitHub Actions：源码生成器与 Rust 测试、Android JVM 单测、lint、原签名 Release APK 构建、证书身份和 SHA256 核查。
- 真机测试：单张、2 张、6 张照片导入，超大图、图库云端 URI、反复编辑与退出、进程终止后的重启恢复、存储失败与账户切换，观察导入可见时间和真正保存完成时间。继续查验 NoteSaveLatency 日志与设备读取性能。
- 此版本为针对明确源码重操作的优化提案，尚无手机实测数据，不承诺即时导入，也不能排除云端相册提供方或设备文件系统的独立迟滞。
