# Android 2.23.2.53 图片后插入块修复候选

## 现象

2026-10-24 用户反馈：知识库编辑器导入图片后，无法在图片后继续增加新的块。截图中图片处于文档末尾，底部仍有“+”插入工具栏。此问题针对 Android 文档块编辑器，不影响图片的导入文件本身。

## 代码原因

编辑器的活动块状态 `activeTextBlockId` 实际承担插入锚点，但导入多张图片后仍指向导入前的文本块。后续工具栏插入因此落在图片之前。即使手动将图片选为活动块，`applyDraftState` 仍仅允许文本块作为活动项，在图片说明编辑以及其他 `recordChange` 操作后重新选中前面的文本块，问题会复现。非文本块没有直接“在后面继续写”的可见入口。

## 修改

1. 图片导入占位符加入草稿后，立即把活动插入锚点设为最后一张图片的稳定块 ID，清理旧的待聚焦文本并释放旧键盘焦点。导入完成时仍使用相同块 ID，后续工具栏“+”、标题、列表、待办等新块插入不再绕回前文。
2. 草稿恢复、编辑图片说明等操作保留仍存在的非文本活动块，文本光标聚焦仅针对 TEXT 块；删除块后仍按原规则安全回退到文本块。
3. 为每个图片块增加可点击的“＋ 在图片下方添加段落”，直接使用所点击图片的稳定 ID，在它后面新增空白文本块，提交已有撤销记录并将焦点移到新块。对于已有图片和新导入图片均可用。
4. 图片说明编辑时也把图片设为活动插入锚点。未修改持久化格式、附件 UUID、恢复日志、同步协议或 Windows 端。
5. Android 版本 2.23.2.53 / versionCode 22322，沿用原正式签名和既有 GitHub Actions 构建流程。
