# Android 2.23.2.47 本机数据读取优化

候选版本，versionCode 22316。基于尚未合并的 PR #41，单独提交后续 PR；Android 签名、同步身份、数据格式及 Windows 版本不变。

## 修复原因与行为

启动中的 `hydrateMissingAttachmentHashes` 把当前便签、修订和历史版本的所有附件交给 `resolvedAttachmentHashes`。原实现逐文件读取并计算 SHA256，即使摘要早已存在；返回后又复制便签结构，最后才发现无需更新。附件体积直接增加每次冷启动等待。

现在先定位真正缺摘要的文件：已有摘要的附件不在这个补齐步骤打开；同一文件的缺失引用只计算一次。若其他版本已声明摘要，所有声明必须合法且一致，并与实际文件相符，才能补齐。缺失文件、损坏文件或冲突摘要不生成新的可信元数据。实际读取、跨工作区复制及同步校验路径未改动。

历史压缩不再在读取工作区前整批执行。恢复完成后延迟两秒启动后台整理，每次事务最多处理一行，间隔一秒，并通过 tryLock 让出用户写入。只有当前账号、可写、全部快照已校验且数据库与镜像未改变时才整理；账号改变、保护状态或异常会停止。压缩仍校验原始内容、摘要、信封、版本及写后读回；成功提交后才更新进程内写入预检凭据，避免整理本身让下一次计时操作重扫全部历史。没有删除历史、跨启动复用凭据或提前开放默认数据。

历史读取使用既有 `(workspace_key, created_at_epoch_millis DESC, id DESC)` 索引。旧 Android 的分批读取用时间与 ID 二元边界推进，避免扫描其他账号或重复排序，也能完整处理相同时间的多条记录。Android 35 及以上的原始语句沿相同索引顺序读取。

当前账号的历史快照仍全部校验。第一次升级遇到未压缩的大量历史仍需读取原始数据；本次消除了前置整批压缩和重复附件读取，不能视为已经验证手机秒开。

## 验证与观察

新增 JVM 测试覆盖 1 万条已具备摘要的引用零文件读取、缺失摘要去重、历史引用约束、文件丢失/损坏/冲突、IO 失败，以及整理事务提交失败和过期凭据。新增真实 SQLite 测试覆盖 2048 条跨账号、乱序 ID、相同/负时间的记录，以 1/16/32 行分页均完整读取当前账号的 682 条记录，并检查查询计划使用索引且没有全表扫描或临时排序。

本地源码生成 153 项测试与上述 6 项 JVM 测试通过。Linux 测试临时修正仓库既有的文件类型引用和常量条件编译问题，未提交这些兼容修正。Android 完整单元测试、lint、原证书签名及 APK 检查由 PR 对应工作流执行，最终状态见 PR。

新增 StartupLatency 阶段日志：legacyMigration、workspaceRestore、draftRecovery、mediaRecovery、missingMediaHashes；继续保留 snapshotPipeline、snapshotStream、ready 和 loadingGate。真机应保留原数据对比强制停止后重开、最近任务移除后重开、离线重开、带大量图片的便签、未提交草稿及切换账号；分别观察界面进入与首次计时/便签保存。未连接用户手机，未测得整机启动耗时，未验证实际账户同步或 Windows 同步服务。
