# Android 2.23.4.15 客户网络画布交互优化

## 原因与目标

原安卓画布只有普通便签和引用现有知识页面两个节点类型，便签文本直接展示为卡片，顶部重复管理按钮占用了过多画布高度。客户介绍人与被介绍人之间的推荐关系只能依靠普通箭头人工维护。

本次围绕手机端真实客户关系管理的首阶段体验，改进画布布局、卡片创建、节点详情、查找和树形排列。画布仍保留自由画布定位、引用知识页面、多画布、撤销重做和账户隔离能力。红包数额、结算与订单尚未实现，不可将本次更改视为财务账本或正式结算系统。

## 新界面与操作

- 画布顶部以单行标题和卡片/关系计数取代两行大号管理按钮，集中提供添加、查找和布局入口。
- 点击卡片展开底部详情面板，而不是扩展主画布底部的操作区。面板可查看名称、备注、上级推荐人与直接推荐人数，并编辑、调整颜色、移除卡片。
- 新增独立客户卡片。创建时输入客户姓名及资料，可以从当前客户详情直接新增被其推荐的客户，原子保存新卡片与连线。
- 便签采用标题和正文独立输入，卡片展示较短摘要，避免把详细正文全部放在标题位置。
- “新建知识页面”直接通过现有知识模块 Rust 创建接口创建，并将新页面引用加入当前画布。“引用已有知识页面”仍然保留为不同操作。
- 查找入口支持筛选客户、便签和页面，并可定位到匹配卡片。
- 更多工具支持推荐层级自动排列、普通网格排列、撤销重做和画布管理。

## Rust 数据约束

新增客户节点类型，保留已有画布 JSON 格式以及原有 note/page 记录。客户姓名位于文本第一行，后续为详情。带上级的客户创建为同一持久化事务。客户连线拒绝重复直接推荐人或循环推荐关系。树形排列仅重定位客户节点，不将知识便签变为客户。

账户数据仍位于本机画布工作区，不因本次修改产生新外发行为。完整客户资料独立建模、跨设备同步、推广绑定期限、订单及红包结算需要独立方案和测试。

## 验收标准

- Rust 客户新增与编辑、持久化重开、重复推荐人/循环拒绝、树形排列与撤销的单元测试通过。
- Android 源码生成测试、产品标识检查、JVM 测试、Lint 和正式签名 APK 构建通过。
- GitHub Actions 的 Android API 35 模拟器安装同一源码提交构建的 APK，实际启动应用、导航到画布、创建客户、点击查看详情、创建推荐下级、树形排列、强制停止并重开确认关系保留。
- 模拟器截图、无障碍树和执行报告作为验收凭据保存。未执行的项目应明确标注，不能用编译结果代替真实 UI 运行。

此文档为候选版本说明，实际结果以 GitHub Actions 对应提交的构建和模拟器运行记录为准。
