# Android 3.0.1：画布问答严重交互回归修复

- 版本：3.0.1
- versionCode：30001
- 正式签名 APK：tenfold_v3.0.1.apk
- 状态：待 GitHub Actions 正式构建及 API 35 模拟器验收

## 故障与修复

分析 3.0 在 GitHub API 35 模拟器中采集的实际截图，发现点击输入框后，原全屏 `Dialog` 受输入法窗口平移影响，标题和“返回画布”在可访问性树中的边界退化为 `[0,0][0,0]`，界面顶部被裁出可视区域，输入框也远离键盘。3.0.1 取消全屏 Dialog 改为主画布内的独立全屏 Compose 页面，直接使用 Activity 的输入法 inset，让页面高度随键盘重新布局。模拟器必须在键盘处于开启状态时检查标题、返回操作与输入区仍然有有效边界；截图保存为证据。

针对空白画布，3.0 显示与当前内容无关的客户收款、推荐问题。3.0.1 改为说明需要先添加卡片或知识页面，禁止提交没有任何卡片来源的画布问题；测试需要真实创建一张便签后，再执行输入框和返回路径验收。

3.0 的提问范围全部收进“范围与隐私”，用户无法一眼判断本次提问是查询整张画布，还是单个节点或其关联网络；3.0.1 将三个可用范围直接显示在标题下方，隐私说明单独按需展开。

3.0 的多轮列表只在旧列表已经位于底部时尝试滚动，新增答案时列表很可能停在上一次答复。3.0.1 在成功写入本机加密历史并完成一次布局帧后，滚动到本轮新答案；原先留在画布外的阅读位置不会因普通进出而强制重置。

3.0 在执行分析或者待保存回答时把“返回画布”直接禁用，容易形成无法退出的体验。3.0.1 增加明确的退出确认。已经安全保存的历史不会删除。对未能保存的本轮回答，界面继续保留重试保存操作；仅在用户明确确认后才放弃本轮未保存结果。

3.0 把“还剩”和“剩余”这些与资金无关的泛化词也判定为待收款问题，可能出现“还剩几张卡片”却呈现财务汇总的混乱内容。3.0.1 收紧金额意图判定，并把本地精确金额摘要由大卡片收为紧凑信息行，减少与模型正文重复争夺阅读空间。

## 验收标准

Android API 35 真模拟器必须安装与当前提交完全一致的正式签名 APK，并执行真实页面交互。提问范围在未展开隐私说明时必须可见，收起隐私说明后不能消失；缺失可访问的输入框必须让测试失败。空问题不能发送，输入后返回画布再重新进入必须保留草稿，系统 Back 键必须正确返回画布。测试输出截图与无障碍树。

无在线 AI 凭证的模拟器不能证明模型问答质量或成功保存新回答，不能以该测试替代已登录有真实数据的人工回归，特别是多轮回答、来源定位、保存失败和跨设备数据安全边界。

## 兼容性

沿用 3.0 的应用包名及原签名证书，版本代码从 30000 递增为 30001；Android Keystore AES-GCM 画布问答存档格式不变，未迁移或删除历史；通用画布、知识页面与客户金额数据结构不变，客户金额继续与风控账本隔离。不更改 Windows 版本及同步协议。
