# Android 2.23.2.59 空白知识页无修改即时退出

## 现象与根因

打开“无标题”空白知识页面，没有输入任何内容，点击返回却长时间显示“保存中”。该现象不仅可能发生在新建空白页，也可能发生在已存在的空白页。现有代码虽然包含未修改页面免保存门槛，但新建页打开时先通过 `upsertNoteAndFlushResult(reason = "note_create")` 写入整个工作区快照；返回时 `blankDraftDeletionEligibleAtEntry` 又可能要求自动删除空白页，即使那是此前已保存的有效页面，也会触发额外的完整快照写入和历史预检。若同时存在队列拥堵，等待进一步放大。没有用户当次完整真机日志，因此无法断言某一次屏幕等待精确耗时于哪一个数据库阶段。

## 解决方法

对于新建 `NoteDraftPreset.BLANK` 知识页，首先使用已有的 `pendingCreatedNote` 暂存编辑器数据，不在打开页面时立刻创建一份持久记录。非空模板继续按原方式持久创建，便签模块的创建行为完全不变。

对于新建和已有的空白知识页，普通返回操作不再被解释为自动删除请求。只有当前编辑状态与入场内容完全相同、编辑代次为零、工作区一致、没有待持久化或待恢复任务时，现有 `canLeaveUnmodified` 门槛才允许立即返回。已存在的空白知识页保持原样，不会因为打开看一眼而被删除。手动明确删除的操作仍按原持久化路径执行。

实际修改标题、正文、属性、非文本块，或进行恢复、编辑后撤销时，仍会被门槛拒绝，并沿用原有草稿队列、退出 checkpoint、SQLite 写入和恢复镜像机制。不会将未经确认的写入伪装为保存成功，不降低账户与历史数据保护。

## 验证

Rust 源码生成器增加仅限知识文档的锚点防漂移测试，确认便签创建路径不变。Android JVM 门槛测试覆盖新建或已有空白的只读退出、明确删除不能跳过、内容有变化不能跳过、编辑后恢复原样仍不能跳过。GitHub Actions 执行 Rust、Android 单测、lint、正式证书签名的 APK 构建和候选预发布。真机需测试新建空白快速返回、已有空白快速返回且原记录仍在、文字编辑后立即退出、编辑后撤销、明确删除、前后台切换和不同账户切换，不能将 CI 成功直接当成真机延时实测。
