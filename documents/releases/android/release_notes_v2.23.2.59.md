# Android 2.23.2.59 空白知识页即时退出

## 现象与根因

用户在知识模块中新建一张“无标题”空白页面，未输入任何内容，点返回后仍长时间显示“保存中”。现有代码虽在 2.23.2.30 添加了未修改页面免保存门槛，但新建页面仍在打开时调用 `upsertNoteAndFlushResult(..., reason = "note_create")`，即使用户不输入也先写入整份工作区快照；退出时 `blankDraftDeletionEligibleAtEntry` 又要求删除刚刚保存的空白页，导致再次进入全量写入和快照预检队列。队列拥堵与账户历史校验可能放大等待时间。现阶段没有该次真机日志，无法将截图中的耗时精确归因到单个持久化阶段。

## 方案

仅针对新建的 `NoteDraftPreset.BLANK` 知识页面，进入编辑器时使用已有的 `pendingCreatedNote` 本地暂存，不立刻提交 `note_create` 持久写入；非空模板保留原来的安全创建与落盘。编辑器由父页面传入 `transientBlankAtEntry`，并由 `appData.notes` 确认该 ID 仍不存在于仓库。当用户从未修改标题、正文或属性且无待恢复/待保存请求时，已有 `canLeaveUnmodified` 门槛可立即完成退出，不会虚构保存凭据、排队删除或阻塞其他写入。

一旦用户实际编辑，`saveRequestGeneration` 和草稿等价判断仍迫使保存经过现有可取消自动保存队列及可靠的退出 checkpoint、SQLite 写入、恢复镜像机制。已存在于仓库的空白页面仍需执行真实删除，不允许误判为临时草稿。工作区切换、历史版本恢复和跨会话回调隔离仍按原保护逻辑执行。

## 验证

增加 Rust 生成器锚点与范围测试，确认只修改知识文档创建，不改变便签；扩充 Android JVM 测试，覆盖临时空白可跳过 IO、已持久化空白必须走删除、修改后不可跳过、已产生编辑代次不可跳过。GitHub Actions 跑 Rust、Android JVM、Lint、签名 APK 及候选预发布。真机还需分别测试秒进秒退、输入一字后退出、输入后撤销、已有空白页面退出和后台/账号切换。CI 通过不等于真机已测出具体时延。
