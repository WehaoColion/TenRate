# Android 2.23.4.2 候选版：回收站 100 天自动永久清理

## 行为

仅安卓端启用自动过期任务。便签与知识文档从首次移入回收站的删除时间开始，保留完整的 100×24 小时；达到时限后，下一次安卓后台任务运行、应用初始化或账户同步完成时批量清理。恢复的文档不参与过期判定，恢复后再次删除重新计时。回收站仍保留手动恢复、永久删除与清空功能。

JobScheduler 在应用启动时注册大约每天运行一次的持久周期任务。安卓休眠、省电策略、强制停止或设备未开机时不能保证恰在第 100 天执行；后续启动和同步会补清。全部在 IO 工作线程执行，不阻塞首页绘制。

## Rust 可靠性与同步边界

Rust 新增 `purge_expired_note_trash_app_data_json`，按 `deletedAtEpochMillis <= now - 100d` 严格判断，采用单次批量变更，复用现有目录解除引用、删除墓碑与共享附件保护。无符合条件记录时返回空结果，避免触发大型 JSON 编解码及持久化。跨工作区写入通过现有工作区检查、互斥量和 `publishAfterDurable` 保护，写入失败时不发布未持久化状态。

Windows 客户端和同步服务均不注册定期删除任务，但安卓生成的墓碑记录仍然可能经账户同步传播到其他设备，这是同一账户共享数据的一部分。墓碑不能跟随回收站条目一同过期，否则旧设备可能复活已删除记录。

清理范围是当前回收站中的文档及其本机无引用媒体，不等价于立即物理抹除所有历史备份或服务端历史快照，后者仍遵循既有保留与同步策略。

## 验证重点

Rust 单元测试覆盖第 100 天的毫秒级边界、较新回收站内容和正常内容保留、恢复取消清理、时钟异常、空操作幂等性、共享附件保护。Rust 源生成器测试检验原生 JNI 声明、后台任务配置、启动路径、事务保存与 Android Manifest 接入。

正式签名 APK 与 Android 真机的休眠/强停/系统回收后行为仍需在 CI 和设备上确认。本次为候选 PR，不宣称已发布或已合并。
