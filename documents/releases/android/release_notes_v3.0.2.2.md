# Android 3.0.2.2：保存链路受控优化与真实阶段反馈

- 版本：3.0.2.2（versionCode 30004）
- 变更基础：3.0.2.1 候选提交 ce778e46；继续在尚未合并的 PR #101 中修订，保留该 PR 原有增量创建能力。
- 范围：Android 知识目录普通新建页面和文件夹，恢复镜像连续保存以及保存弹窗；Windows、同步格式、SQLite 表结构及加密数据规则不变。

## 安全边界

新建页仍由原 Rust 全工作区验证父级、历史孤立子项、节点身份和保护状态。只有新增节点不与现有节点重名、恰好比以前增加一个对象、所有旧节点保持同一个内存对象且其他业务数据完全不变，才使用仅新增节点的修订及规范化。任一条件不成立自动执行原全量修订及规范化；任何运行时无法完成的规范化也维持既有失败与禁止写入路径。

原生 Rust 创建时仍需编码和解析整工作区，最终仍存储完整 SQLite 快照。**本版没有引入增量数据库存储，也不承诺消除大型知识库首次历史验证的分钟级等待**。大幅调整 SQLite 提交单位与历史验证机制必须先有大数据、断电恢复和跨版本兼容验收，不能直接取消检查。

恢复镜像：对于 encoded 长度不超过 100 万字符的已验证镜像，在保持原文件标记及工作区匹配约束下增加有上限的强引用，降低垃圾回收后反复读取和解析旧镜像的概率。其余仍使用弱引用，不降低原有完整性前置判断。

## 用户可见行为

知识目录明确区分等待前序保存、正在写入本地数据两种状态。超过 8 秒提示保存仍在进行。弹窗仅在持久化成功后退出，继续保留工作区锁、成功凭据与数据失败回退规则。

新增 `hierarchy_write_lock` 和 `hierarchy_normalize` 阶段计时，记录是否使用新增节点专用规范化路径，保持固定的脱敏诊断名。

## 验收与已知限制

Rust 源码生成器测试与已有节点创建规格测试，连同 Android Release 正式签名、JVM 回归和 Android 35 模拟器安装、启动、新建、等待各保存状态消失、强制终止与重启后持久化复查一起运行。验收必须以 PR 本提交的签名 APK 为准。

模拟器没有真实数千页面和成百历史快照，也不代表用户实际设备的存储性能。后续真机应重点采集 `explicit.queue_wait`、`hierarchy_write_lock`、`hierarchy_normalize`、`snapshot_preflight`、`preflight_native_verification`、`sqlite_commit` 和 `recovery_mirror` 的耗时。

## 大型 SQLite 快照的历史读取

`SnapshotPayloadCursor` 对大于 CursorWindow 容量的数据分块读取，过去每次只读取 128 KiB。改为严格受限的 512 KiB 块，在不改变同一事务、行标识、长度核对和哈希/信封验证的前提下减少每条历史快照的 SQLite 子查询数。普通 8 MiB 历史载荷的 SQL 取块次数理论上由 64 降到 16，仍以真机时间为准。Rust 原生 SQLite 大 UTF-8 载荷测试及 Android JVM 分块边界测试同步更新。
