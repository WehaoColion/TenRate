# Android 2.23.4.5：AI 图片输入与 Rust 多模态问答

## 功能范围

安卓“直接问 AI”和“问知识库”现在可以通过系统图片选择器选择最多五张图片。发送前展示缩略图，可逐张移除或清空；只在用户点击发送时读取图片字节。图片随本轮问题作为 Responses API 的 input_image 部分发送，与原有的纯文本问答兼容。成功后会话显示附图数量，可主动再次引用某轮的图片，未选择时不会默认重复上传。

## Rust 实现

Rust 校验图片实际格式，只接受 JPEG、PNG、GIF、WebP；单张不超过 6 MiB、合计不超过 20 MiB，拒绝超限而非截断。图片在 IO 线程从 Android 授权的 content URI 有上限地读取，JNI 接口仅向当前 AI 请求传递显式选择的图片，不写入知识正文、账号同步、持久历史或日志。采用 original 画质以保护截图文字与图表细节。

DeepSeek 当前的 deepseek-flash 可识别图片，deepseek-v4-pro 不支持。UI 阻止对不支持视觉的官方 DeepSeek 模型发图，并提供设置入口。文字问答沿用旧方法。官方 Pro 的连接探针改为文字和 JSON Schema 测试，避免因图片不可用误判连接失败；模型的真实可用性仍以接口响应为准。

## 安全与兼容性

所有内容仍受现有工作区、授权资料和请求失效机制约束。加密笔记不因图片上传功能被访问。图片选择器无需相册全盘权限；会话仅保留临时 URI 供用户再次选择引用，进程结束不保留图片副本。图片可能自带元数据，界面明确告知。Agent 模式仍维持独立的明确资料授权流程，不在本轮自动添加图片工具。

本候选的发布版本为 2.23.4.5，versionCode 22335。由于 2.23.4.4 的 Agent UX PR #65 仍独立审核，正式合并顺序请先处理 #65，并在合并前核对版本历史冲突。

## 回归验证

- Rust 模块单元测试：图片格式识别、大小上限、无图路径、历史消息的角色隔离与图片仅附在最后用户消息
- Rust 生成器测试：图片选择器模板、受限 URI 读取与清空操作
- Android Release：源代码生成、Gradle 单元测试、Lint 与 Release APK 构建

正式发版前还需在实际安卓设备使用真实 API Key 测试 5 张图片、截图文字、高分辨率图表、重复引用、拒绝权限及网络中断。不得把 Rust 测试通过等同于在线视觉识别实测通过。
