# Android 2.23.3 手机端知识子项完整展开与紧凑列表

## 用户问题

父页面中“子项 5”展开后实际只显示3条，剩余2条必须再次点击“查看全部”进入独立目录。这使当前层级的页面被无意义地截断。同时，每行默认显示“页面 · 0 个子项”造成屏幕空间浪费，正文编辑区被进一步推低。

## 实现

Android 由 Rust 源码生成的 `KnowledgeHierarchyUi.kt` 原先使用 `children.take(3)`。现改为直接枚举当前父页面全部直接子项，删除多余的“查看全部”按钮。首次打开父页面时，子项默认展开；手动收起和再次展开沿用 `rememberSaveable(workspace, parentId)` 本地界面状态。

新增仅供父页面内使用的紧凑子项行，最小高度52dp，长标题最多两行，保留页面/文件夹标识和进入箭头。没有下一级且无特殊状态的页面不再显示“0个子项”；有子项、只读、加密、冲突等需要解释的状态继续显示精简说明。完整目录仍使用原来的 `KnowledgeHierarchyRow`，不影响拖动排序和辅助功能操作。

没有引入独立内层滚动容器；子项与正文仍共享外层页面的纵向滚动。展开和收起仅更新 Compose 状态，不调用 Repository、草稿写入或同步。点击子页面仍通过原有 `navigateHierarchy` 保护当前未保存草稿，不绕过持久化屏障。未修改 Windows 版本及同步协议、账户存储格式。

本次为针对手机父页面的局部交互修复。对于数百或数千子项的父页面，全部同层级行仍位于同一个外层列表条目中，没有声称已实现可见范围虚拟化或一键跳至正文；这些场景需要后续专门的性能与手势验收，不用重新引入三项截断来掩盖问题。

## 版本与构建

用户明确指定 Android 版本名为 `2.23.3`，属于本次对常规四段递增规则的明确例外。对应 `versionCode` 从22328增加至22329。Rust 产品身份、Gradle 构建与应用内更新记录同步更新；候选发布脚本兼容三段与四段数字版本名，仍校验同一正式签名证书及APK SHA256。

新增 Rust 源码生成模板的回归断言，防止未来恢复前三项截断，保障折叠仍只是本地UI状态。PR 发起时 CI 实际构建和真实安卓设备验收尚未完成，不能因此宣称APK已经生成或交付成功。

## 真机验收重点

使用0、1、3、5、20和大量直接子项分别打开父页面。确认五项全部可见、标题不重叠、滚动稳定、展开与折叠不会出现保存提示；点击子项后能正常返回父页面。测试多层文件夹、只读/加密/异常节点、字体放大、屏幕旋转、编辑后立刻进入子项、跨账户切换及独立目录拖动排序。尤其确认大量子项时是否出现卡顿；此项不能只用构建成功代替。
