# Android 3.0.2.57 修复知识目录动效绘制与模拟器验收误判

本版针对 3.0.2.56 的真实 API 35/36 模拟器证据，分别修正知识目录渲染开销、分享长图标题检测和长文本输入探针。保存时限、历史负载和验收阈值均未放宽。

## 知识目录渲染

3.0.2.56 的 API 35 动效记录包含 102 帧，其中 82 帧被判定为卡顿，P90 帧耗时 89ms。时间线显示渲染线程等待和 GPU 完成耗时偏高。本版将导航动画状态收敛到 Rust 生成的 `KnowledgeDirectoryMotion` 类型，强制使用单个有界离屏合成层，只作用于资料卡；目录列表、滚动状态和触控坐标不随动画平移。移除重复的全屏视口裁剪，并在知识场景禁用底部导航阴影、环境背景和脉冲重绘。弹簧参数与原交互路径保持不变。

签名前仓库契约检查禁止恢复整页 `AnimatedContent`、全屏位移或第二个视口裁剪，并要求资料卡离屏层存在。检查使用历史全屏双目录动画结构作为反向样本；删除关键离屏层必须失败，单纯更换视觉样式不得失败。

## 分享长图标题检测

API 35/36 的真实分享图片中，前置正文段落会换行成两条图像墨迹带。旧探针固定从第 5 条墨迹带取样，误把正文末行当成一级标题，导致正确的 H1/H2/正文序列被误报。本版改为扫描连续的 H1、H2、正文、H1、H2、正文六条序列，兼容前置段落换行，并保留字体层级反向时必须失败的检查。

## 便签长文本输入

API 35 的压力验收曾在版本创建前观察到 247/249 字节，API 36 同一场景通过。旧探针一次性发送整行 40 位数字。本版改为每 10 位分块投递，并在每一行后读取真实编辑器内容进行精确比对。缺字仍会立即失败，不会自动补写，也不会进入版本耗时统计。原有 8 秒版本创建预算、SQLite 竞争和退出重启完整性检查保持不变。

## 尚待本版签名模拟器确认

上述修改均需由本版签名 APK 在 API 35、API 36 模拟器重新验证。尤其需要确认知识目录 P90 帧耗时和卡顿比例是否真实下降，不能用 APK 上传成功或探针编译成功代替运行验收。500,000 条历史快照的恢复仍有较长耗时，继续单独观察，不将其与单次保存耗时混为一谈。

PR 未通过本版全部签名模拟器验收前，不合并主分支。
