# Android 2.13.5.2：知识模块现代轻拟物 UI

## 改造范围

只改变 Android 端知识模块的视觉表达。以较克制的 Smartisan 式物件识别为方向，文件夹采用暖色折页与前唇形态，页面采用纸张折角与细微行线。图标由原有 Rust 源码生成链输出为 Android Compose Canvas 绘制，不增加下载图片或图标资源。

完整目录中的页面与文件夹行采用统一的柔和圆角表面和轻微阴影。文档内子项保持至少 52dp 的紧凑触控行，背景使用低对比度材质层，并显示一致的纸张或文件夹图形。完整目录的当前位置增加物件标识与子项数量，新建子页面按钮明确为主操作；新建子文件夹保留次级操作的视觉层次。知识首页紧凑头部增加同一套对象标识与最近编辑提示。

## 交互和数据边界

沿用 Android 现有的完整子项展开、折叠、根目录进入、目录返回、拖动排序和上下移无障碍动作。目录行外部的 Material Surface 不劫持长按手势，保留现有目录拖动占位、提交前快照校验和失败恢复。图标本身是装饰对象，不作为独立点击目标。

普通文档继续默认编辑。没有修改正文编辑逻辑、锁定/加密状态、当前工作区、版本管理、数据持久化、同步格式或传输。Windows 客户端和服务端不变，Android 账户与原签名保持一致。

颜色根据应用主题背景亮度选择浅色或深色物件，不使用真实纸张纹理位图，避免缩放与列表滚动时重复加载大图片。

## 验收要求与当前状态

本 PR 需通过 Rust 源码生成器测试、Android 版本身份测试、正式 Android 构建与原签名校验。GitHub Actions 在同一提交的正式签名 APK 构建成功后，启动 API 35 Pixel 模拟器，实际打开应用，进入知识目录，新建测试文件夹，并保存启动、目录、创建弹窗及结果截图和无障碍树。

必须区分真实模拟器运行结果与源代码静态检查。PR 创建时不提前声称签名构建或模拟器通过。深色模式、不同文字大小、文件夹数量较多时的性能和长期日常使用体验仍应结合实际截图及后续设备验证。

APK 候选文件名为 `tenfold_v2.13.5.2.apk`，内部 `versionCode` 为 22350。主分支仍维持现有版本直至按用户指令合并。
