# Android 3.0.2：画布问答结果优先、来源可查

- **版本**：3.0.2
- **Android versionCode**：30002
- **依赖**：PR #99 的 Android 3.0.1 画布问答基础功能，先合并底层 PR 后方可合并此 PR
- **范围**：只优化 Android 画布问答，不更改 Windows、同步协议、风控账本

## 问题

此前直接渲染外部 AI 返回的 Markdown，导致待收合计与来源卡片埋在冗长解释里，人民币内部整数单位和 [n] 引用密集出现。顶部显示重复的画布统计，输入栏和“回到最新回答”又占据额外空间。用户无法在关键金额与原始画布客户之间直接导航。

## 设计

在查询款项时，本地 Rust 对当前许可范围内的所有客户汇总金额和人数；新增结构化 `pendingClients`，按照金额降序，至多输出 12 位有实际待收余额的客户，每条附真实节点 ID，并明确是否截断。这些字段只进入本机结果展示与原有加密历史，不要求 DeepSeek 推导总额。展示金额统一使用元和两位小数，点击具体客户可返回画布定位。超过展示上限时总额仍来自全部范围客户，不允许按展示样本重新求和。

保持现有模型的自然语言分析、历史对话上下文与完整原始答案加密存档不变。对于金额问题，优先展示本地可信的结果和客户明细，将 AI 分析收至可展开的说明；对于一般知识问答仍直接展示正常模型回答。UI 阅读副本去除引用数字堆砌和冗余的“（132,000 分）”括号注记，引用通过具名卡片入口按需展开。旧记录缺少新字段时使用默认值继续读取，历史来源可从当前节点标题恢复。

收束顶部画布名称与卡片数，缩小输入操作；仅当实际停留在较早的消息条目时，才显示“回到最新回答”。

## 验收边界

`android-release.yml` 在独立分支构建签名候选 APK，`android-canvas-question-emulator.yml` 下载**同一提交**的 APK，在 GitHub API 35 模拟器启动、实际创建画布卡片并打开问答，检查范围、输入框、软键盘、草稿恢复、禁发与系统返回，上传 PNG 和无障碍树。Rust 领域测试核对结构化客户明细排序、金额准确性、最多12条与截断情形。

模拟器没有正式 DeepSeek API 凭据，故不能证明真实多轮模型质量。来源卡片变更时依然显示历史快照提示，原始模型回复保留，以便用户自行核实。PR 保持待合并状态，不以未完成构建声称验收通过。
