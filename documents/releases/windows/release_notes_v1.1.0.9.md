# Windows 1.1.0.9 Android 功能对齐源码候选

基线：GitHub main 中 Windows 1.1.0.8 源码候选与 Android 2.23.2.55。仅 Windows 分支 PR，未构建或替换正式 Windows 安装程序和同步服务。必须区分源码功能、CI 构建、Windows 原生交互及正式交付。沿用原存储、账户、公网身份、同步协议和 Android APK。

## 这次接入的功能

1. **AI 连续追问**：桌面问答使用共享 `complete_android_conversation`，请求中只复用同一会话已成功完成的最多八轮、总计 24,000 字符的完整问答；每条失败或取消的请求不进入上下文，切换模式、范围、账户和接收方清空上下文。单次预览绑定完整问题、范围与历史摘要，保持一次性授权。聊天消息与输入框处在同一问答界面，不强制每次跳转阅读窗口。对任意回答仍可打开离线公式阅读、复制或保存当前回答。
2. **记账优先**：财务默认进入日账；顶部快捷添加当天收入、支出，两种入口复用原有记账记录模型和真正保存，不预先声称已持久化。切换日期、月季年及原风控计算继续存在。存在无效金额草稿时快捷新增禁用。更多备份与恢复功能折叠，不再挤占日常操作首屏。
3. **Agent 分步流程**：任务目标、选择资料、确认发送、执行和结果审阅分区展示，加入常用任务模板。结果草稿未保存时关闭需要额外确认；已完成并保存后可开始下一任务。没有改变真实 API 请求上限、授权来源范围、深度复核与保存证据门禁。
4. **图片后继续编辑**：图片导入后将最后一张仍存在的图片 ID 保持为插入锚点；知识页提供在图片下方新增段落的直接动作。不会改动原图片 ID、媒体日志、SHA256 或跨端同步结构。

## 经审查不应照搬的 Android 专属改动

Android 2.23.2.46 至 2.23.2.55 的 Kotlin SQLite 历史分页、ART 基线配置、CursorWindow、JNI 调用开销、仅当前快照认证凭据均属于 Android 专用启动与认证链。Windows 已使用不同状态存储和异步启动机制，不得直接移植 Android 的历史认证豁免。Android 2.23.2.52 的流式 SHA256 在 Windows `desktop_note_media.rs::copy_source_to_synced_temp` 现有实现已存在，不能将它冒充为新增能力。

## 仍需进一步性能或视觉验收

Windows 批量图片导入仍按原安全日志与提交顺序进行，尚未实施全工作区多图事务合并。长图 PNG 仍使用原桌面 Canvas 绘制，复杂公式和 KaTeX 的所见即所得导出还未核实；知识阅读器的公式渲染已存在。Windows 多页面交错保存与启动时间不能凭 Android 日志推断，应对照 Windows 实测。便签软换行及待办换行需以 Windows 预览、HTML 与 PNG 的真实输出另行核对。

## 回归检查

- 运行 GitHub Actions Windows 编译、主程序测试和共享库测试；任何红灯都不得称为已验收。
- 交错进行两轮 AI 追问、取消一次响应、切换直接/知识模式及账户和接收模型，确认新范围没有带入旧回答及旧知识来源。知识模式的历史回答不能变成本轮来源事实。
- 检查原风控账目中的精确分金额、默认当天、确认撤销、无效金额禁止保存、跨月与历史日期、删除墓碑及备份恢复功能。
- 检查 Agent 目标模板、资料选择上限、授权、取消、深度复核、失败保留和已保存后继续新任务，不允许未保存草稿被窗口关闭静默丢失。
- 单图、多图及历史图片块添加段落，测试键盘、活动块和保存后重新进入，图片 ID 与附件元数据应保持不变。
- 验证 Windows 本地数据保存、关闭恢复、同步服务登录自启动以及本机和公网健康身份，再按仓库正式发布流程替换可执行文件。

## 发布边界

本 PR 未修改 Android 版本、APK、签名、同步协议、服务部署与现有 Windows 正式清单。Windows 源码版本仅从 1.1.0.8 候选增加至 1.1.0.9 候选。真实电脑验收、签名 EXE 和同步身份复核完成之前不能称为正式发布。
